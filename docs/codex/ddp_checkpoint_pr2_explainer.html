Background: Why DDP Broke Attribute Access

In normal PyTorch, a model submodule might expose attributes directly:

student.backbone.patch_embed.proj.weight

But after DistributedDataParallel wraps a module, the raw module lives under .module. DDP does not proxy arbitrary child attributes like patch_embed. So this works:

student.backbone.module.patch_embed.proj.weight

And this can crash:

student.backbone.patch_embed.proj.weight

The original bug: the checkpoint loader needed the patch-embed input channel count, but the training path had already wrapped student.backbone in DDP. Direct .patch_embed access therefore raised AttributeError.

Anna's master commit 7a42442 fixed the training path by adding an unwrap helper. PR #2 keeps that idea and improves the surrounding implementation.

Mental Model: Checkpoint Keys vs Model Keys

Checkpoint loading is mostly a key-matching problem. A saved tensor only lands in the model if its string key matches what model.state_dict() expects.

Plain module keys

backbone.patch_embed.proj.weight
backbone.norm.weight
dino_head.mlp.0.weight

A checkpoint saved before DDP wrapping usually looks like this.

DDP-wrapped submodule keys

backbone.module.patch_embed.proj.weight
backbone.module.norm.weight
dino_head.module.mlp.0.weight

Once each student submodule is wrapped, PyTorch inserts .module. into the state-dict key path.

The PR's key remapper bridges that mismatch. It checks whether the model expects DDP-style keys, and if so, transforms backbone.x into backbone.module.x only when that transformed key exists in the target model.

1. Load checkpointRead teacher, model, student, state_dict, or raw dict.
2. Normalize rootsStrip or add prefixes so keys line up with the student container shape.
3. Adapt channelsUse the model's patch-embed input channels to adapt checkpoint convolution weights.
4. Match targetUse target model keys to remap DDP names and reject a load where nothing matched.

Change 1: One state_dict() Call Instead of Four

The current code computes model keys once in checkpointer.py around lines 483-488:

model_keys = set(model.state_dict().keys())
if _state_dict_uses_ddp_prefix(model_keys):
    chkpt = _remap_checkpoint_keys_for_ddp(chkpt, model_keys)

Then the same model_keys is reused for the final matched-key check around line 521:

matched_keys = [k for k in filtered_state.keys() if k in model_keys]

Before

  • Call model.state_dict() to detect DDP key prefixes.
  • Call it again inside the remapper to get target keys.
  • Call the DDP detector again inside the remapper.
  • Call it again for the matched-key safety check.

After

  • Call model.state_dict() once.
  • Use that key set to detect .module..
  • Use that same key set for remapping.
  • Use that same key set to prove something matched before loading.

Why this is behavior-preserving: the remapper only needs the target model's key set. Passing that set in, instead of recomputing it, should not change the mapping result.

Reviewer note: the DDP detector is still string-based: any(".module." in key for key in model_keys). That matches this repo's wrapping shape, but it is not a general DDP type check. For this PR, it is consistent with the existing design and tests.

Change 2: Defensive Eval-Path Unwrap Repair

The eval loader is described as non-distributed, but the old code still had the risky direct access pattern:

model.patch_embed.proj.weight.shape[1]

The first repair unwrapped only that input-channel read. The June 10 repair is more complete: compute the target once, use it to read in_chans, and use the same target for load_state_dict:

target = _unwrap_module(model)
state_dict = adapt_patch_embed_input_channels(
    state_dict, target.patch_embed.proj.weight.shape[1]
)
msg = target.load_state_dict(state_dict, strict=False)

For a normal eval model, target is model. For a DDP-wrapped eval model, target is model.module, where patch_embed exists and where the prefix-stripped checkpoint keys actually match.

Why the second repair mattered: checkpoint keys have their leading module. stripped before loading. If the code then calls load_state_dict on the still-wrapped DDP object, the model expects module.* keys while the checkpoint has prefix-free keys. With strict=False, that can silently match zero keys and leave the eval model at random init weights.

What now proves it: the wrapped eval tests assert weight equality, not just no exception. The pre-repair code was red-checked: three wrapped-path tests failed while the plain-path test passed; after 42812b5, the suite reports 32 passing tests.

Important nuance: the validation doc says real eval jobs build a plain teacher backbone. That means the DDP-wrapped eval test is a regression guard for a latent bug, not evidence that production eval normally uses DDP here. A Slurm training smoke would not add much for this repair because the changed branch is CPU-only and unreachable from real training.

Change 3: Defer grad_norm.item()

clip_grad_norm_ returns a tensor-like norm. Calling .item() turns a one-element GPU tensor into a Python number. That sounds harmless, but it forces the CPU to wait until the GPU has produced the value.

In this training loop, the old scalar read happened after backward but before optimizer.step(), step_end_event.record(), and step_end_event.synchronize(). That is the wrong time to force a host sync if you care about DDP overlap and CUDA graph performance.

Before

metrics_dict[f"{k}_grad_norm"] = (
    grad_norm.full_tensor().item()
    if isinstance(grad_norm, DTensor)
    else grad_norm.item()
)

The CPU waits mid-step for the norm scalar.

After

metrics_dict[f"{k}_grad_norm"] = (
    grad_norm.full_tensor()
    if isinstance(grad_norm, DTensor)
    else grad_norm.detach()
)

The norm remains tensor-shaped until the logging path, after the explicit step sync.

The key safety argument is in train.py lines 651-668. Immediately after grad clipping, metrics are converted to tensors, stacked, all-reduced, and written back into metrics_dict:

metrics_values = torch.stack(
    [torch.as_tensor(v, dtype=torch.float32, device=total_loss.device).detach()
     for v in metrics_dict.values()]
)
torch.distributed.all_reduce(metrics_values, op=torch.distributed.ReduceOp.AVG, ...)
metrics_dict = dict(zip(metrics_dict.keys(), metrics_values))

Why this is intended to preserve behavior: downstream logging was already receiving tensors after this all-reduce block. The PR changes the pre-reduction value from a Python float to a 0-dim tensor, and torch.as_tensor(...) handles both.

Why the review called this SAFE

  • Downstream consumers accept tensors. MetricLogger.update converts tensor inputs with v.item() in dinov3/logging/helpers.py lines 25-30. The wandb block handles DTensor, tensor, and scalar values explicitly. The JSON writer emits SmoothedValue.median, which returns a Python scalar around lines 168-171.
  • The original tensor does not leak forward. At train.py line 668, metrics_dict is rebuilt from the all-reduced metrics_values stack, so the dict no longer points at the original grad_norm.detach() object.
  • The scalar read moved after the explicit sync. step_end_event.record() and step_end_event.synchronize() happen around train.py lines 692-696. Logging and wandb scalar conversion happen later around lines 724-754.
  • Clipping semantics are unchanged. The call to torch.nn.utils.clip_grad_norm_ still happens under the same condition, over the same student modules, with the same max_norm=cfg.optim.clip_grad.
  • No CUDA graph alias hazard was found. Compile/cudagraph wrapping is applied inside model blocks in ac_compile_parallelize.py lines 65-127, and graph step marking is inside ssl_meta_arch.py lines 379-388. Grad clipping and metric reduction happen after forward_backward returns, outside that captured submodule scope.

DTensor nuance: full_tensor() may still perform a collective. The PR removes the host scalar sync from .item(); it does not claim to remove every distributed operation for DTensor. The main measured path is DDP, where grad_norm.detach() stays on GPU.

How I Would Review This PR

  1. Start with the diff shape. Confirm the PR is only the four intended files and does not pull in experiment artifacts from perf-ddp-fullgraph.
  2. Review the checkpointer helpers. Make sure _unwrap_module is only used where a simple one-layer unwrap is enough, and that the key remapper cannot drop or duplicate tensors unexpectedly.
  3. Review the DDP branch in init_fsdp_model_from_checkpoint. Confirm model_keys is computed before DDP/FSDP2 branching and reused for DDP detection, remapping, and matched-key validation.

  6. Separate code safety from test gaps. The Commit-3 issue was a real code bug in a constructed defensive path and is now repaired. Remaining gaps are narrower: no outer eval-builder wiring test and no pytest for the train-loop grad-norm path.
  7. Use jobs 68971/69781 for the checkpoint-load question. They prove the PR's load path against a real RGB checkpoint and a DDP-wrapped 5-channel student. Do not confuse the later 2-GPU partial-node iter-0 hang with a checkpoint-load failure.

Mini Glossary

Term Plain meaning in this PR
DDP PyTorch DistributedDataParallel. It wraps modules for multi-GPU training and stores the raw module under .module.
state_dict() A mapping of parameter/buffer names to tensors. Loading checkpoints is mostly aligning checkpoint keys with model keys.
.module. prefix The extra key segment that appears when a submodule is wrapped in DDP, for example backbone.module.norm.weight.
.item() Converts a one-element tensor into a Python scalar. On GPU tensors, that conversion forces the CPU to wait for the GPU.
cudagraphs CUDA graph capture/replay. It is sensitive to unexpected syncs and dynamic behavior in the training step.
DTensor PyTorch distributed tensor type used in the FSDP2 path. Its full_tensor() can involve communication.
