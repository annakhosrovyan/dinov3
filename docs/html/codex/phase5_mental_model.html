Concepts over chronology

The useful model is: local compute is decent; multi-GPU communication is eating the win.

Phase 5 makes more sense once you separate local GPU efficiency from distributed scaling. Many apparent contradictions are just those two forces pulling in different directions.

The System Picture

Each rank processes multi-crop ViT work. Local compute is mostly transformer matmuls and attention over global and local crops.
FSDP2 shards parameters and communicates around blocks. All-gather brings shards in; reduce-scatter moves gradients out. With many blocks, the collective schedule is frequent.
Activation checkpointing changes the live memory set. Selective and full AC save memory by recomputing parts of the forward pass during backward.
The current bottleneck is not one missing low-level knob. Existing traces show NCCL dominates kernel time and overlaps poorly with compute.

Mental Models

MFU is a speedometer, not the engine

MFU says how much of dense H100 BF16 peak the training loop is converting into useful model FLOPs. Low MFU does not say why it is low. Here, the single-GPU numbers are much better than 8-GPU numbers, so the missing MFU is mostly a distributed-scaling problem.

AC can be faster when memory is the limiter

Textbook AC trades compute for memory and often slows training. In this repo, selective AC improved the bs=96 matrix because the smaller live activation set appears to reduce memory-system pressure enough to offset recompute.

Bigger batch helps locally, then loses at scale

bs=128 is faster per image on one GPU, which means local kernels like the bigger shape. At 8 GPUs, that gain disappears, so the likely culprit is communication, scheduling, rank variance, or overlap.

LL128 is a knob, not a strategy

Forcing LL128 helped in the clean Stage A run. Even if that gain is real, it only moves the current 7-8% MFU regime by a modest amount. It does not explain how to reach the 30% target.

How to Read New Results

Observation Likely Meaning Do Next
Same config changes by 10-20% across runs Node/start-state variance is larger than the knob being tested. Do not narrate a mechanism. Compare only controlled same-window runs.
Mean improves but CV explodes The result may be a mixed regime or a straggler pattern. Cut late windows and inspect per-rank timing before trusting it.
Memory changes but img/s does not The knob is useful for stability, not necessarily throughput. Classify it as fallback/safety, not performance default.
1-GPU improves but 8-GPU regresses Local compute is not the blocker; distributed effects are. Look at NCCL, FSDP2 scheduling, rank stragglers, and overlap.

Glossary

ACActivation checkpointing. Saves less activation memory during forward and recomputes later during backward.
Selective ACCheckpointing policy that saves selected expensive operations instead of recomputing everything.
Full ACCheckpointing policy that recomputes whole wrapped blocks. Usually saves more memory than selective AC.
FSDP2PyTorch's sharded data-parallel training path. It shards model state and coordinates all-gather / reduce-scatter collectives.
ZeRO-3Sharding style where parameters, gradients, and optimizer state are partitioned across ranks.
reshard_after_forwardWhether FSDP releases gathered parameter shards after forward. True is the current safe default.
NCCLNVIDIA communication library used for GPU collectives like all-gather, reduce-scatter, and all-reduce.
LL128An NCCL protocol. For this workload, forcing it beat NCCL's automatic protocol choice in Stage A.
NORSShort local label for TORCH_NCCL_AVOID_RECORD_STREAMS=1.
MFUModel FLOP utilization. Useful model FLOPs divided by dense hardware peak.
HFUHardware FLOP utilization. Includes extra recompute work, so it can rise when AC adds recomputation.
CVCoefficient of variation. Standard deviation divided by mean; useful for measuring jitter across different throughput scales.
Steady statePost-warmup window after compile and early allocator effects settle. For this project, early windows can be misleading.
StragglerA rank that finishes a step later than others. In synchronized training, one slow rank slows everyone.
OverlapHiding communication under computation so NCCL work does not extend the step as much.
Regime shiftWhen the same config behaves like a different system across runs, usually due to node state, warmup state, contention, or long-run effects.
