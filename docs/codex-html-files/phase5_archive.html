Timeline

2026-05-07 to 2026-05-08: nsys setup and trace capture

Initial nsys jobs failed because module load was unavailable on GPU nodes. Later traces captured usable evidence: NCCL dominated kernel time and overlap was poor.

still relevant

2026-05-13: early bs=96 baseline outlier

One gpu08 baseline reported much higher MFU. Later node-variance work showed it was not representative of the common gpu01/gpu05/gpu07 regime.

superseded baseline

2026-05-14: selective AC first became real

Selective AC ran cleanly at bs=96 and cut memory by about 10.6 GB. The initial "free win" language was later softened because one paired run was not enough for a universal claim.

foundation result

2026-05-15: AC and batch matrix

bs=96 selective AC became the throughput candidate. bs=96 full AC became the memory fallback. bs=128 remained investigational and then was parked after same-node reruns.

decision-shaping

2026-05-16: single-GPU disambiguator

bs=128 was faster per image on one GPU, proving local compute likes the larger batch. Since 8-GPU did not benefit, the lost gain is a distributed scaling issue.

conceptual anchor

2026-05-18: NCCL Stage A

LL128 was the clean positive result. NVLS, lower NTHREADS, and larger BUFFSIZE regressed. NORS was a secondary standalone win.

LL128 signal

2026-05-18: NCCL Stage B

LL128 + full AC looked reasonable, NORS stacking looked bad, and bs=128 + LL128 was too mixed-regime to trust at 300 iterations.

partly revised

2026-05-18: NCCL Stage C

Longer runs exposed a regime shift: C1 did not reproduce Stage A A2, C2 did not rescue bs=128, and C3 contradicted B1 on NORS stacking. This changed the confidence language around production claims.

variance warning
