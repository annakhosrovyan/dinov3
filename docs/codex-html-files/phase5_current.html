Current truth first

Phase 5 is a communication-bound FSDP2 tuning effort, not an endless knob sweep.

The useful summary is: keep the safe bs=96 operating point, prefer selective AC for throughput, keep full AC as the memory fallback, park bs=128 for production, and treat LL128 as promising but not a whole strategy.

Safe target
bs=96

FSDP2 ZeRO-3 with reshard_after_forward=true. This is the current production-safe batch size.

Best measured matrix cell
1351 img/s

bs=96, selective AC, reshard true, steady window on gpu07 before LL128.

Dominant trace signal
70-80%

NCCL share of kernel time in earlier nsys traces, with weak compute overlap.

Operating Verdict

Use bs=96 + selective AC as the throughput candidate. Keep bs=96 + full AC as the memory fallback. Do not promote bs=128. Do not add NORS by default. LL128 remains the only NCCL knob with a clean positive reading, but its exact production magnitude is uncertain because Stage C did not reproduce Stage A cleanly.

Selective AC: default candidate Full AC: memory fallback LL128: promising bs=128: parked NORS: omit

Decision Board

Topic Decision Confidence Why
FSDP2 platform Stay on FSDP2 ZeRO-3 High DDP path is closed for this phase; FSDP2 is the long-run platform.
Batch size Use bs=96; park bs=128 High bs=128 has local compute upside on 1 GPU, but no demonstrated 8-GPU mean-throughput upside.
Activation checkpointing Selective first, full as fallback High Selective is the throughput candidate. Full saves much more memory at small measured throughput cost.
NCCL_PROTO=LL128 Promising; use as candidate knob Medium Stage A was a clean +12% win, but Stage C exposed regime variance and did not cleanly anchor production throughput.
TORCH_NCCL_AVOID_RECORD_STREAMS=1 Do not add by default Medium Standalone win did not survive cleanly when stacked with LL128. Simpler default is easier to defend.
More NCCL knob sweeps Stop unless a specific hypothesis appears High NCCL env knobs can move a few percent. They are not the path from 7-8% MFU to the lab target.

Next Lever

Highest-level question

Where does the missing MFU come from? The strongest existing answer is poor multi-GPU scaling: the single-GPU selective-AC run is around 20-22% MFU, while 8-GPU runs are around 7-8%.

Candidate next work

Focus on levers that change communication frequency, overlap, or model-side work structure. Examples: gradient accumulation if it actually reduces useful syncs, FSDP2 grouping/prefetch behavior, per-rank straggler analysis, or compile/CUDA graph blockers.

Do Not Re-litigate By Default

NVLS

Explicit NVLS did not show a useful signal. Park unless a new trace points there.

NTHREADS / BUFFSIZE

Both regressed in Stage A. Do not keep tuning them without a new reason.

bs=128 production

Interesting diagnostically, not better operationally. Its lower CV in one window is a clue, not a production case.
